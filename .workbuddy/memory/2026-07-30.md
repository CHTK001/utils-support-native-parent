## 诊断：utils-support-redis-starter 源码缺失
- 现象：该模块目录在 `utils-support-middleware-parent/` 下，但 `src/main/java` 中 **0 个 .java 文件**；只剩骨架（pom.xml、README.md、src/main/resources/META-INF 下 6 个 SPI 声明文件 + target 里拷贝的 resources，无 .class / 无 jar）。
- README 写明"共 17 个类"（RedisClient、RedisConfigCenter、RedisDataTable、RedisDeduplicator、RedisServiceDiscovery、RedissonDispatcherProvider、RediSearchEngine、RediSearchQueryConverter、RedisEngine、SimpleRedisDataSource 等），SPI 实际声明了 6 个实现类（包名 `com.chua.redis.support.*`）：
  - RedissonDispatcherProvider / RedisConfigCenter / RediSearchEngine / RedisServiceDiscovery / RedisDataSink / RedissonLockProvider
- 全仓 grep 这些类名：仅 SPI 文本与 README 引用，无任何 .java 实现；`spring-support-redis-starter` 里有个同名 `com.chua.starter.redis.support.debounce.RedissonLockProvider`，但属 Spring 层、不同包，非同一套。
- 恢复可能：仓库 `git` 尚无任何 commit（"No commits yet"），`git fsck` 悬空 blob 中也无 `com.chua.redis` 内容 → 无法从版本历史恢复。源码要么从未进入此工作副本，要么在仓库初始化前被删。
- 与 mqtt 的区别：mqtt 是有完整代码但放错父工程；redis 是模块骨架在、实现类全无。
- 后续待用户决策：A) 从备份/其它 clone/远程分支找回 17 个类；B) 按 SPI 契约 + 接口（DispatcherProvider/ConfigCenter/Engine/ServiceDiscovery/DataSink/LockProvider）+ redisson/jedis 重新生成实现。
