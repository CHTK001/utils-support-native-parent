# 2026-07-29 工作记录

## 一、MiniMind 推理优化（续 7/28）
- 修复 DJL `Input mismatch` 报错：`processInput` 原返回空 NDList()，导致 DJL 校验模型输入签名失败。
  改为仍返回结构正确的 NDList（input_ids + attention_mask），同时缓存分词结果供 `generateGreedy` 复用。
- 性能优化（MiniMindTranslator.java）：
  - ORT session 显式 `setIntraOpNumThreads(8)` + `setMemoryPatternOptimization(true)` + SEQUENTIAL
  - `FloatBuffer` 直接读最后一位 logits，不再物化整个 `[1,seq,6400]` 三维数组
  - token buffer 预分配，消除每步 `new long[]` 扩容
  - 缓存 outputName / hasAttentionMask / vocabSize，消除每步迭代获取
  - 新增计时日志 `Generated N tokens in Xms (avg Yms/token)`
- 结果：64 tokens / 5548ms（86.7ms/token）。**根本瓶颈是无 KV Cache（O(N²) 重复计算），代码层优化只能止血**，真正提速需重新导出带 KV Cache 的 ONNX（Docker 172.16.0.40 重跑导出脚本 + past_key_values I/O）。用户未确认是否做 KV Cache 版。

## 二、检测类模型下载地址审计 + 补充（用户任务）
- **审计结论**：检测类模型（注册到 `ImageDetector.class`）共 38+ 个，分布在 5 个 DJL 引擎注册器。
  - 11 个已有 HuggingFace 下载地址（可用）
  - 15 个无下载地址（6 参 `reg()`），且文件系统实测其相对路径指向的模型文件**全部缺失** → 当前完全不可用
- **关键约束**：`ModelRegistry` 有 `if (get(modelId)==null)` 守卫，同名 ID 重复注册被忽略。
  因此"补充下载地址"必须改现有 `*ModelRegistrar`，不能新建模块重复注册。
  项目无独立 `models-starter` 模块；模型注册全部在各 `utils-support-deeplearning-*-starter` 的 registrar 里。
- **路径解析**：`resolveModelPath` 先查 relativePath/本地/zip，全失败才 `tryDownloadFromRemote`。

## 三、检测模型下载 URL 可达性验证 + 修复（用户任务）
- **验证方法**：沙箱 curl 被阻（DNS 劫持 127.0.0.1 + SSL 吊销检查失败），改用 WebFetch 逐个访问 HuggingFace 仓库页面 + API 确认文件是否存在。
- **验证结果**（8 个补充 URL 中 4 个有问题）：

  | 模型 | 原 URL | 状态 | 修复 |
  |------|--------|------|------|
  | scrfd-face-detector | RuteNL/SCRFD-face-detection-ONNX/2.5g_bnkps.onnx | ✅ 3.29MB | 无需修复 |
  | ultra-face | onnxmodelzoo/version-RFB-320/version-RFB-320.onnx | ✅ 1.27MB | 无需修复 |
  | owlv2 | onnx-community/owlv2-base-patch16-ONNX/onnx/model.onnx | ✅ 614MB | 无需修复 |
  | yolo5/7/8-plate-detect | morsetechlab/yolov11-license-plate-detection/license-plate-finetune-v1x.onnx | ✅ 228MB | 无需修复 |
  | yolo8-general-layout | XiaHan19/.../yolov8n_layout_general6.onnx | ❌ 文件不存在（仓库只有 general6-8n.pt） | 删除下载URL，改回6参reg（无ONNX版本可用） |
  | yolov8s | onnx-community/yolov8s | ❌ 仓库404不存在 | 改为 lquint/yolov8s-onnx/onnx/model.onnx（44.8MB，downloadFileName=yolov8s.onnx） |
  | pytorch-yolov5s | ultralytics/yolov5s | ❌ 仓库404（应为 Ultralytics/YOLOv5 大写） | 改为 Ultralytics/YOLOv5/yolov5s.pt |
  | pytorch-yolov8n | ultralytics/yolov8n | ❌ 仓库404（应为 Ultralytics/YOLOv8 大写） | 改为 Ultralytics/YOLOv8/yolov8n.pt |

- **关键教训**：HuggingFace 仓库名大小写敏感，`ultralytics/yolov5s`（小写）≠ `Ultralytics/YOLOv5`（大写）。API `api/models/{org}/{repo}` 可验证仓库存在性 + 列出 siblings（文件清单）。
- **未修复的**：yolo8-general-layout 因 HuggingFace 上无对应 ONNX 文件（qihoo360/360LayoutAnalysis、juliozhao/DocLayout-YOLO-DocStructBench 也都只有 .pt），暂时改为内置模型（需手动放置 .onnx 文件）。
